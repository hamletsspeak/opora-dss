# Лаборатория `/lab`

Рабочая область включает семь разделов. Данные текущего редактора живут в памяти вкладки; скачайте JSON перед закрытием. API_TOKEN, если настроен сервером, вводится в верхней панели и также не сохраняется в браузерное хранилище.

1. **Постановка.** Введите текст, выберите провайдера и сформируйте черновик либо импортируйте JSON/CSV. JSON можно редактировать вручную. «Проверить» показывает отчёт валидатора; в черновике доступны источники, неизвестные поля и журнал преобразований. После проверки данных отметьте флажок и подтвердите задачу. Подтверждение снимается при каждой правке или замене задачи. Импорт нескольких постановок в редактор открывает первую; весь набор запускается в «Экспериментах».
2. **Расчёт.** Выберите метод, режим M/W, число итераций, seed, распределение интервалов и генератор весов. Параметры сценариев, моды треугольных распределений и alpha Дирихле редактируются в JSON задачи. Явные настройки отдельных ячеек имеют приоритет над распределением по умолчанию. Ошибки входа/режимов показываются вместо исправления чисел. Точные значения не меняются.
3. **Результаты.** Выбор режима, таблица среднего score, среднего ранга, pBest и pWorst. Доступны фактические настройки неопределённости, паспорт, сопоставление режимов и экспорт JSON/CSV. Результат относится к сохранённой в эксперименте постановке, даже если редактор позже изменён.
4. **Устойчивость.** Рассчитывает чувствительность текущей подтверждённой постановки с выбранными в «Расчёте» параметрами. Таблица показывает базовое значение, ближайшую границу смены лидера, величину изменения и нового лидера. По каждому весу доступны диапазоны лидерства, схема перераспределения весов, способ расчёта и точность. Отсутствие границы относится только к исследованному диапазону; никакой фиксированный pBest-порог не используется.
5. **Эксперименты.** Запуск текущей задачи во всех четырёх режимах или пакета CSV/JSON. История хранится на сервере; эксперимент можно открыть, повторить с проверкой идентичности результата или загрузить его постановку в редактор. Для CSV/JSON пакетного импорта используется действующий формат экспериментального модуля. Ошибки каждого файла/режима сохраняются в отчёте. Отдельные режимы могут оказаться несовместимы с постановкой, например W fixed без точных весов.
6. **Электронная торговля.** Импорт CSV или синтетического демо; сопоставление полей, проверка доступных критериев/действий, выбор SKU и временных окон. Допущения последствий задаются JSON-переопределениями; полный перечень попадёт в постановку. Черновик можно передать в редактор для подтверждения. Rolling backtest показывает прогноз, фактические продажи, MAE/RMSE/WAPE, покрытие диапазона и лидеров по режимам. История не доказывает эффект невыполненных действий. Подробности — [ecommerce.md](ecommerce.md).
7. **Сравнение LLM.** Загрузите контрольный набор и список провайдеров, выберите постановки/модели и запустите сравнение. Кнопка указывает число вызовов; облачные модели расходуют их квоты. По умолчанию выбран mock. Можно открыть ранее скачанный `report.json`; сводная таблица показывает JSON/schema, precision, recall, F1 и неподдержанные факты, а полный отчёт содержит исходные ответы, ошибки и паспорт. Скачайте результат: HTTP endpoint не сохраняет его автоматически. Протокол — [llm-benchmark.md](llm-benchmark.md).

Факты, интервалы, экспертные допущения и моделирование различаются в происхождении и metadata постановки. pBest — частота первого места в заданной модели, а не гарантия результата или вероятность бизнес-успеха. Для задач из электронной торговли сначала согласуйте поля и допущения с владельцем данных.
