# Запуск Лаборатории и Docker

## Локальная работа

Требуется Node.js 24 и npm. Из корня проекта:

```powershell
npm ci
Copy-Item .env.example .env
npm run build
npm start
```

Откройте `http://localhost:8787/lab`. `/` сохраняет диалоговый интерфейс, `/api/health` — проверка процесса. Для разработки `npm run dev` запускает API :8787 и Vite :5173; Лаборатория доступна на `http://localhost:5173/lab`.

`LLM_PROVIDER=mock` работает без сети. Ручной JSON и расчёты не требуют LLM. Ключи OpenAI/Yandex и адреса локальных моделей задаются только в серверной `.env`; все переменные описаны в `.env.example`. При включённом `API_TOKEN` в Лаборатории раскройте «Доступ к API» и введите токен: он хранится в памяти вкладки. Диалоговый интерфейс пока не имеет поля ввода токена. Публичный health не проверяет доступность модели; она проверяется отдельно через API LLM. Не помещайте секреты в переменные `VITE_*`.

В локальном режиме эксперименты сохраняются под `DATA_DIR` (по умолчанию `data/runs`), значение `memory` включает временное хранилище. Эта директория исключена из git. JSON-логи в stdout содержат HTTP-статусы, время, идентификаторы запросов и события `started`/`stopping`; штатные логи не содержат тела исходных данных.

## Docker Compose

Требуется Docker Engine/Desktop с Compose. Подготовьте `.env` из примера, затем:

```powershell
docker compose build
docker compose up -d app
docker compose ps
docker compose logs --tail=50 app
```

Сборка запускает тесты и TypeScript/Vite build. Runtime устанавливает только production-зависимости; `tsx` включён в них для исполнения серверного TypeScript. Сервер работает от `node`, не от root. В образ попадают сервер, ядро, клиент и синтетические примеры; `.env`, история экспериментов, результаты запусков и git исключены из контекста сборки.

Приложение доступно на `http://localhost:8787/lab`. Внешний порт меняется через `APP_PORT`, адрес публикации — через `APP_BIND_ADDRESS` (по умолчанию `127.0.0.1`). Порт/host/dataDir внутри контейнера заданы Compose. Healthcheck проверяет `/api/health` встроенным fetch Node; Ollama для него не требуется. `app-data` хранит эксперименты, пакеты и метаданные LLM в `/app/runtime`; обычные `down`/`up` сохраняют volume. `docker compose down -v` удаляет историю — используйте только осознанно. Резервное копирование volume выполняйте средствами вашей инфраструктуры.

`APP_COMMIT` можно передать как идентификатор сборки; без него при отсутствии git в образе commit будет неизвестен. Node-образ и Ollama сейчас используют изменяемые теги; для фиксируемого релиза следует закрепить проверенные digests. Версия v1.0 этим набором изменений не объявляется.

## Локальная модель в отдельном сервисе

```powershell
docker compose --profile ollama up -d
docker compose exec ollama ollama pull qwen2.5:7b-instruct
```

После загрузки модели установите `LLM_PROVIDER=ollama`, `OLLAMA_MODEL=qwen2.5:7b-instruct` в `.env` и пересоздайте app: `docker compose --profile ollama up -d app`. Профиль не загружает модель автоматически и не требует GPU. Модели сохраняются в `ollama-data`. API Ollama наружу не публикуется. `OLLAMA_DOCKER_BASE_URL` задаёт адрес из контейнера app, по умолчанию `http://ollama:11434`; `OLLAMA_BASE_URL` используется при обычном локальном запуске без Docker. Если Ollama находится на другом хосте, укажите доступный контейнеру URL.

При отсутствии Ollama ручные расчёты остаются доступны. Конфигурация fallback задаётся явно; benchmark никогда не переключается на другую модель. Производительность и доступность конкретной модели нужно проверять на целевом сервере.

## HTTPS и эксплуатация

В текущем Compose приложение привязано к localhost и готово к размещению за reverse proxy на том же сервере. Домен и сертификаты задаются после получения инфраструктурных параметров; Caddy в этот набор не включён. За доверенным reverse proxy включите `TRUST_PROXY=true`. Для отдельного frontend укажите точные origin в `CORS_ORIGIN`. Текущий API_TOKEN — общий токен доступа, не разделение пользователей/тенантов; историю видят все обладатели этого токена. HTTP benchmark выполняет один пакет одновременно на процесс, не является очередью распределённых задач.

Для приватных данных используйте свой сервер: `.env` и файлы результатов не должны публиковаться как статические ресурсы. Интерфейс и весь API v1 в этом документе обслуживаются Express. Прежние функции Vercel `api/*.ts` остаются legacy API; для `/lab` со всеми разделами нужен Express, описанный выше.
