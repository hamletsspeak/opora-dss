# Аудит исходной версии (v0.1.0, коммит `eac7c52`)

Аудит выполнен перед переработкой в версию 1.0. Цель — зафиксировать исходную архитектуру, найденные дефекты и карту изменений.

## 2. Текущий алгоритм MCDA (`runRobustMcdm`)

1. На каждой из `samples` итераций (по умолчанию 2000, seed 42, ГПСЧ Mulberry32):
   - семплируются веса функцией `sampleWeights`;
   - интервальные оценки семплируются равномерно, точечные остаются как есть.
2. Матрица нормализуется min–max по столбцу с учётом `min/max` (столбец с нулевым размахом → 0.5).
3. На одной и той же выборке считаются три метода:
   - «TOPSIS-like» — TOPSIS на min–max-нормализованной матрице (идеал = 1, антиидеал = 0), основной;
   - Weighted Sum (WSM);
   - VIKOR (v = 0.5), меньше Q — лучше.
4. Агрегация: `winRate`/`pBest`, `pWorst`, средний ранг, средний score; согласованность лидеров методов.
5. Вывод об устойчивости: одно правило `winRate < 0.55 → «Лидер неустойчив»`, плюс `|Δscore| < 0.05`.

## 3. Найденные дефекты и несоответствия требованиям

| № | Где | Проблема | Требование |
|---|---|---|---|
| D1 | `sampleWeights` | Точный вес при `weightUncertain=false` **не фиксирован**: он семплируется из Дирихле с α = max(0.05, 20·w) и затем нормируется, то есть меняется на каждой итерации | 6.1 |
| D2 | `sampleWeights` | Параметры α для неопределённых весов сами случайны (`4 + rng()*2` и т. п.) — скрытый гиперприор, не отражённый в настройках | 6.3, 6.4 |
| D3 | `sampleWeights` | Гамма-распределение для дробной части формы аппроксимировано как `frac·Exp(1)` — это не Gamma(frac); итоговое распределение не соответствует заявленному Дирихле | 6.3 |
| D4 | `sampleWeights` | «Soft ordinal»: попарная перестановка весов high/low с последующей перенормировкой — эвристика, меняющая распределение и не документированная | 6.3 |
| D5 | `runRobustMcdm` | Пропущенная оценка подменяется на `0` (для критерия `min` это лучшее значение) | 5.1, 7 |
| D6 | `orderByScore*` | Ничьи разрешаются по индексу (`a.i - b.i`) — систематическое смещение в пользу первой альтернативы | 7, 8 |
| D7 | `sensitivityFromRanking`, `SensitivityViz` | Устойчивость определяется одним порогом 55%; нет анализа чувствительности по параметрам и порогов смены лидера | 8 |
| D8 | контракт | Нет режимов M/W: неопределённость M и W всегда включена одновременно и определяется неявно | 6 |
| D9 | контракт | Распределение интервала (равномерное) выбрано неявно; нет треугольного и сценарного; нет правила точечной оценки | 6.2 |
| D10 | API | Входная `SessionState` принимается без валидации (`as SessionState`); zod подключён, но не используется | 5.1, 14.3 |
| D11 | `server/agent.ts` | Ядро формализации привязано к OpenAI SDK; нет абстракции провайдера, health-check, классификации ошибок | 4 |
| D12 | `server/agent.ts` | При ошибке LLM выполняется **молчаливый** переход на регулярные выражения (`fallbackParse`); пользователь не видит, что LLM не использовалась | 4.2 |
| D13 | `normalizeCriterion` | Направление критерия, выданное LLM, молча переопределяется регуляркой (например, «срок службы» → `min`), без журнала изменений | 5.2 |
| D14 | хранение | Нет паспорта запуска: версии приложения, коммита, хеша данных; аудит хранится только в памяти процесса | 9.3 |
| D15 | эксперименты | Нет пакетного режима, импорта CSV/JSON, повторного запуска и экспорта CSV | 9 |
| D16 | домен | Нет сценария e-commerce/SKU и временной проверки train/test | 10, 11 |
| D17 | тесты | Нет тестового раннера; самотест проверяет только форму результата | 14.2 |
| D18 | развёртывание | Нет Dockerfile/compose; CORS `*`; путь к секретам агента зашит в код (`/cursor/stores/...`) | 14 |
| D19 | `TOPSIS-like` | Метод называется TOPSIS, но использует min–max вместо векторной нормализации — отличие не задокументировано | 7 |
| D20 | Python | Порт повторяет дефекты D1–D6 | 7 |

## 4. Что сохраняется

- Mulberry32 как базовый ГПСЧ (детерминирован, достаточен для MC).
- Три метода (TOPSIS c min–max, WSM, VIKOR) и общая выборка для сравнения методов.
- Разделение «LLM пишет текст — ядро считает цифры».
- Диалоговый UI Klar и его маршруты `/api/chat`, `/api/demo`, `/api/analyze`, `/api/audit`.
